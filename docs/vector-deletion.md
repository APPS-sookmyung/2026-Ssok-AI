# 벡터 삭제 API

Spring은 사용자 권한을 확인하고 북마크 또는 스페이스의 DB 삭제가 커밋된 뒤 해당 API를 호출합니다. 팀원 탈퇴 시에는 해당 사용자의 검색 권한만 갱신합니다.

| 대상 | 요청 |
| --- | --- |
| 북마크 하나 | `DELETE /api/v1/ai/vectors/{bookmark_id}` |
| 스페이스 전체 | `DELETE /api/v1/ai/vectors?space_id={space_id}` |

- 양쪽 서버에 삭제 전용 공유 시크릿을 설정합니다. Spring은 `X-AI-Secret` 헤더에 시크릿을 넣고, AI는 환경변수 `VECTOR_DELETE_SECRET`과 비교합니다. 운영 전송에는 HTTPS 또는 보호된 서비스 간 연결을 사용합니다.
- 삭제 직후와 이미 삭제된 대상 모두 빈 본문의 204를 반환합니다. 유효한 ID는 1 이상의 BIGINT입니다. 스페이스 ID가 없거나 유효하지 않으면 422를 반환합니다.
- 인증 헤더 누락·불일치는 401, AI 시크릿 미설정은 503입니다. 설정 오류는 설정을 고친 뒤 재시도합니다. 일시적인 네트워크·DB 오류 후에는 같은 요청을 다시 보낼 수 있습니다.
- 배포 전에 [003 마이그레이션](../sql/003_vector_deletions.sql)을 적용하고 모든 벡터 쓰기 프로세스에 이 버전을 반영한 뒤 Spring 삭제 호출을 활성화합니다.
- AI는 삭제 대상 ID 기록과 벡터 삭제를 한 트랜잭션에서 커밋합니다. 저장과 삭제가 겹치면 트랜잭션 잠금으로 순서를 정합니다. 분석이 늦게 끝나도 삭제한 북마크와 스페이스는 다시 색인하지 않습니다. 삭제 기록은 원문이나 임베딩을 포함하지 않습니다.
- 이 API는 Spring이 ID를 재사용하지 않는 영구 삭제를 전제로 합니다. 북마크 이동에는 호출하지 않습니다.
